仮想記憶とページング

仮想記憶は、補助記憶（SSD・HDD）を使って、主記憶を実際より大きく見せる仕組みです。プログラムを同じ大きさのページに区切り、いま必要なページだけを主記憶に置きます。これがページングです。

下のページ番号を押して「参照」してみましょう。主記憶のページ枠は3つしかありません。

プログラムのページ押すと参照する
主記憶ページ枠 3個
補助記憶主記憶にないページ
ページフォールト：0 回
ページプログラム（仮想記憶）を一定の大きさに区切ったもの。
ページ枠主記憶を同じ大きさに区切ったもの。ページを1つ入れられる。ページフレームともいう。
ページフォールト参照したページが主記憶にないときに起きる割込み。これをきっかけに OS がページを読み込む。
ページイン補助記憶から主記憶へページを読み込むこと。
ページアウト主記憶から補助記憶へページを追い出すこと。空いている枠がないときに行う。
流れ：参照したページが主記憶にない → ページフォールト → 空きがなければ1ページをページアウト → 必要なページをページイン。
補助記憶は遅いので、ページフォールトは少ないほどよい。そこで「どのページを追い出すか」が重要になります。

ページ置換アルゴリズム

追い出すページの決め方です。名前と「何を追い出すか」をセットで覚えます。

FIFO
First In First Out		最も古くに読み込まれたページを追い出す。途中で何回参照されても順番は変わらない。
見るもの：主記憶に入った時刻
LRU
Least Recently Used		最後に参照されてから最も時間がたっているページを追い出す。参照されるたびに「最近使った」扱いになる。
見るもの：最後に使った時刻
LFU
Least Frequently Used		参照された回数が最も少ないページを追い出す。
見るもの：使った回数

LRU の R は Recently（最近）、LFU の F は Frequently（頻繁に）。「最近使っていない」か「あまり使っていない」かの違いです。

FIFO と LRU を1手ずつ比べる

参照するページの順番（参照列）とページ枠の数を決めて、1手ずつ進めてみましょう。最初はどの枠も空です。

参照列はページ番号をカンマか空白で区切って入力できます（20個まで）。表が横に長いときは、表の部分を横にスクロールできます。

頻出パターンと注意点

  • 表を書いて数える：参照列を横に並べ、枠の中身を1手ずつ書く。上のシミュレータと同じ表を紙に書けるようにしておく。
  • 最初に空の枠へ読み込むときもページフォールトに数える。数え忘れが多いところ。
  • FIFO と LRU の違いが出るのは「枠にあるページを参照したとき」。FIFO は何も変わらないが、LRU はそのページが「いちばん最近使った」ページになり、追い出されにくくなる。
  • LRU のほうが少なくなることが多いが、必ず少ないとは限らない（上の「FIFO が少ない例」）。
  • スラッシング：主記憶が足りず、ページフォールトが多発してページイン・ページアウトばかりになり、処理が急に遅くなる現象。対策は主記憶を増やす、同時に動かすプログラムを減らす、など。
  • プログラムは一部分を集中して使う性質がある（局所性）。「最近使ったページはまたすぐ使う」と考えるのが LRU。
