# SQLクイズ

基本情報技術者試験の SQL に慣れるための、ブラウザで動く練習サイトです。
元の表と「欲しい出力結果」を見て SQL を書くと、ブラウザの中の SQLite（データベースソフト）で実際に実行して採点します。

- 公開先：https://ino-inori.github.io/fe-zukai/sql/
- 判定は ⭕正解・△惜しい・❌不正解 の3種類
- 成績はブラウザの中（localStorage）にだけ保存します。サーバーには何も送りません

---

## 1. 自分のパソコンで動かす

ファイルをダブルクリックして開く（`file://` で開く）と、問題データを読み込めずに動きません。
次の手順で「簡易サーバ」（このフォルダの中身をブラウザに渡すだけの小さなプログラム）を起動してから開きます。

1. PowerShell（またはターミナル）を開き、`fe-zukai` フォルダに移動する。

   ```bash
   cd D:\Hiroaki\Documents\ClaudeCode\fe-zukai
   ```

2. 簡易サーバを起動する（Python に付いている機能です。止めるときは `Ctrl + C`）。`py` は Windows で Python を呼び出すコマンドです。

   ```bash
   py -m http.server 8780
   ```

3. ブラウザで次のアドレスを開く。

   - クイズ：http://localhost:8780/sql/
   - 問題データの検査：http://localhost:8780/sql/check.html

> このパソコンでは `python -m http.server 8780` と打つと、Python ではなく Microsoft Store の案内が動いてしまいます（Windows の「アプリ実行エイリアス」のため）。`py` を使ってください。
> `py` も使えないパソコンでは、Python を入れた場所を直接指定します（例：`C:/Users/…/Python310/python.exe -m http.server 8780`）。

初回に読み込んだ後は、インターネットにつながっていなくても動きます（必要なファイルはすべてこのフォルダの中にあります）。

## 2. 公開する（GitHub Pages）

このサイトは GitHub Pages（GitHub の無料の静的ホスティング）で公開しています。
設定は済んでいて、リポジトリ `ino-inori/fe-zukai` の `main` ブランチを push すると、数分後に公開サイトに反映されます。
ビルド（変換作業）はありません。フォルダの中身がそのまま公開されます。

公開する前のチェックリスト：

1. **問題データの検査が全部 ✔ か**：http://localhost:8780/sql/check.html を開き、一番上に「✔ ○○ 問すべて合格しました」と出ることを確かめる。
2. **プログラム（`js/` や `sql.css`）を変えたときは版番号を上げる**：`index.html` と `check.html` の中の `?v=3` を `?v=4` のように1つ増やす。こうしないと、見る人のブラウザに古いプログラムが残ることがあります（問題データ `problems.json` は毎回確認して読み込むので不要です）。
3. 変更を記録する（コミット）。

   ```bash
   git add -A
   ```

   ```bash
   git commit -m "SQLクイズに問題を追加"
   ```

4. GitHub に送る（push）。これで公開サイトに反映されます。

   ```bash
   git push
   ```

5. 数分待ってから https://ino-inori.github.io/fe-zukai/sql/ を開いて確かめる。古い表示のままなら、ブラウザで再読み込み（`Ctrl + Shift + R`）します。

すべてのページに `<meta name="robots" content="noindex, nofollow">` を入れているので、検索エンジンには載りません（URL を知っている人だけが見られます）。

## 3. 問題を足す・直す

問題はすべて `data/problems.json` に書いてあります。プログラムを触らずに、このファイルに追記するだけで問題を増やせます。
「欲しい出力結果」の表は手で書きません。模範解答の SQL を実行した結果から自動で作ります（写し間違いが起きません）。

### 手順

1. `data/problems.json` を開き、似た種類の既存の問題を1つコピーして、`"problems": [ … ]` の中に貼り付ける（問題と問題の間はカンマ `,` で区切る）。
2. `id`（重複しない名前）、問題文、表、模範解答などを書き換える。
3. http://localhost:8780/sql/check.html を開き直して、全部 ✔ になることを確かめる。✖ が出たら、右のメモ欄に理由が出ます。
   カンマの付け忘れなど JSON の書き方を間違えたときは、「読み込みに失敗しました … (line 2546 column 1)」のように、間違いのある行の番号が出ます（その行の少し前を見直します）。
4. クイズ画面で実際に解いてみる。

問題はファイルに書いた順に、カテゴリごとに並びます（ホーム画面の問題番号はファイルの順番）。

### 項目の説明

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 問題の名前。ほかと重ならない英数字（例：`join-08`）。成績はこの名前で保存されるので、公開後は変えない |
| `category` | ○ | 分類。次のどれか：`基本のSELECT` `条件指定` `あいまい検索` `NULL` `集計関数` `グループ化` `結合` `副問合せ` `データの変更` `表の定義` `ビュー` |
| `difficulty` | ○ | 難易度 1〜3。1 = 1つの句で解ける、2 = 句の組み合わせ、3 = 結合・副問合せ・集計と絞り込みの組み合わせ |
| `question` | ○ | 問題文 |
| `tables` | ○ | 元の表（1〜3個）。`CREATE TABLE` の問題だけは 0 個でもよい。書き方は下の例 |
| `checkTables` | △ | INSERT / UPDATE / DELETE / CREATE TABLE / CREATE VIEW の問題で、実行後に比べる表やビューの名前 |
| `answerSql` | ○ | 模範解答。最後に `;` を付ける |
| `altTables` | ○ | ごまかし防止用の別データ。表の名前と行だけを書く（列は `tables` と同じものが使われる）。`CREATE TABLE` の問題では空 `[]` でよい |
| `orderMatters` | | 行の並び順も採点するか（`ORDER BY` を求める問題だけ `true`） |
| `compareColumnNames` | | 列名も採点するか（`AS` で名前を付けさせる問題だけ `true`） |
| `requiredKeywords` | | 必ず使わせる構文（例：`["HAVING"]`）。無いと結果が合っていても不正解 |
| `hint` | ○ | 「ヒント」ボタンで出す文 |
| `explanation` | ○ | 正解後・「答えを見る」で出す解説。ひっかけやすい点や、SQLite と試験の標準SQLの違いもここに書く |
| `trapSqls` | | ひっかけの誤答例。検査ページで、これらが必ず❌になることを確かめる |
| `emptyOk` | | 別データで結果が空になるのが正しい問題だけ `true` |

### 例：SELECT の問題

```json
{
  "id": "sel-09",
  "category": "基本のSELECT",
  "difficulty": 1,
  "question": "社員表から、給与が 300000 以上の社員の氏名を表示せよ。",
  "tables": [
    {"name": "社員",
     "columns": [["社員番号", "INTEGER"], ["氏名", "TEXT"], ["給与", "INTEGER"]],
     "rows": [
       [1, "佐藤", 320000],
       [2, "鈴木", 280000],
       [3, "高橋", 300000]
     ]}
  ],
  "answerSql": "SELECT 氏名 FROM 社員 WHERE 給与 >= 300000;",
  "altTables": [
    {"name": "社員",
     "rows": [
       [11, "小林", 310000],
       [12, "加藤", 260000],
       [13, "吉田", 300000],
       [14, "山田", 450000]
     ]}
  ],
  "orderMatters": false,
  "compareColumnNames": false,
  "requiredKeywords": [],
  "hint": "「以上」は >= です。",
  "explanation": "300000 ちょうどの社員も入るので > ではなく >= を使います。",
  "trapSqls": ["SELECT 氏名 FROM 社員 WHERE 給与 > 300000;"]
}
```

- 値が無いところ（NULL）は `null` と書きます。文字は `"…"` で囲みます。
- `columns` の型は `INTEGER`（整数）・`TEXT`（文字）・`REAL`（小数）のどれかにしておくと安全です。
- 主キーを付けたい表は `"primaryKey": ["部署コード"]` を足します。

### 採点の種類（自動で決まります）

| 模範解答 | 比べるもの | 必要な項目 |
|---|---|---|
| `SELECT …` | 実行結果の表 | — |
| `INSERT` / `UPDATE` / `DELETE` | 実行した後の表の中身（行の順番は問わない） | `"checkTables": ["社員"]` |
| `CREATE VIEW …` | 作ったビューを SELECT した結果 | `"checkTables": ["ビュー名"]` |
| `CREATE TABLE …` | 作った表の列名・型・主キー・NOT NULL・外部キー | `"checkTables": ["表名"]` |

### よい別データ（altTables）の作り方

別データは「答えの値を直接書いた SQL」を見抜くためのものです。次のようにすると、ごまかしを見抜けます。

- 本データとは違う人・違う値にして、正しい SQL の結果が本データと変わるようにする（同じだと検査ページに「△ 注意」が出ます）。
- 正しい SQL の結果が空にならないようにする。
- 境目の値（「以上」なら、ちょうどその値）を入れておく。
- `WHERE 給与 > 301250` のように、本データの平均などを数字で直接書く答えも見抜けるか考え、見抜けるようなら `trapSqls` に入れておく。

### 気をつけること

- `orderMatters` が `true` の問題では、並べ替えの列に同じ値が2つ以上あると、正しい SQL でも順番が変わって不正解になることがあります。並べ替えの列の値は重ならないようにします。
- 日本語の並び順（`ORDER BY 部署名` など）は文字コード順になり、五十音順にはなりません。漢字や仮名の列での並べ替えは出題しないのが無難です。
- 小数は小数第2位で丸めて比べます。

## 4. 採点のしくみ（参考）

1. SQL が1文だけか、使えない命令（`ATTACH` `DETACH` `PRAGMA` `load_extension`）が無いかを確かめる。
2. 毎回まっさらなデータベースを作り、元の表を入れて、入力された SQL を実行する。
3. 模範解答の結果と比べる。比べ方は次のとおり。
   - 列は、数と順番が一致すること。
   - 行の順番は、`orderMatters` の問題だけ比べる。
   - 重複行は、件数まで一致すること。
   - NULL どうしは一致とみなす。
   - 小数は小数第2位で丸めて比べる。
   - 文字は大文字・小文字も区別して完全一致。
4. 別データでも同じように比べて、両方一致したときだけ正解にする。
5. 一致して、最後に `;` があれば⭕、無ければ△。
6. 一致しなければ「自動修正版」を作り、それで一致すれば△にする。修正の中身は次の4つ。
   - `;` を補う。
   - くっついた語の間にスペースを入れる（`ORDERBY` → `ORDER BY`）。
   - 1〜2文字の綴りミスを直す（`SELCT` → `SELECT`）。キーワード・表名・列名が対象。
   - 全角を半角にする。

   直した箇所の種類だけを伝え、正しい綴りは教えません。文字列（`'…'`）の中身は変えません。
7. それでも一致しなければ❌。自分の結果と欲しい結果を並べて表示し、SQLite の英語のエラーは日本語で説明します。

## 5. ファイルの一覧

| ファイル | 役割 |
|---|---|
| `index.html` | クイズの画面（ホーム・出題・結果） |
| `check.html` | 問題データの検査ページ |
| `sql.css` | SQLクイズだけの見た目（色などは `../css/style.css` と共通） |
| `js/grader.js` | 採点のしくみ（実行・比較・惜しい判定・エラーの日本語化） |
| `js/app.js` | 画面の動き |
| `js/progress.js` | 成績の保存 |
| `data/problems.json` | 問題データ |
| `vendor/sql.js-1.10.3/` | sql.js 1.10.3（ブラウザで動く SQLite）。npm 公式パッケージから取得。MIT ライセンス（同じフォルダの `LICENSE`） |

成績は、ブラウザの localStorage の `fe-zukai:sql:progress` に保存されます。ホーム画面の「成績を消す」で消せます。
